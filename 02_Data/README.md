#  Data

## Data Source

This project uses a synthetic healthcare dataset generated with **Synthea**, an open-source patient simulation tool that creates realistic, privacy-safe electronic health records (EHRs).

Unlike publicly available healthcare datasets with limited scope, Synthea produces longitudinal patient records that closely resemble real hospital data while containing no personally identifiable information (PII). This makes it ideal for developing and demonstrating healthcare analytics solutions.

The dataset contains information spanning patient demographics, clinical encounters, diagnoses, medications, procedures, healthcare costs and insurance coverage.
## Dataset Overview

The project integrates multiple healthcare datasets into a centralized analytics platform.

The core datasets include:

| Dataset | Description |
|---------|-------------|
| Patients | Demographic information including age, gender, ethnicity, location and socioeconomic attributes. |
| Encounters | Clinical visits containing encounter type, diagnosis, provider, duration and healthcare costs. |
| Conditions | Patient diagnoses recorded across different encounters. |
| Medications | Prescription history including medication descriptions, dispensing dates and costs. |
| Procedures | Medical procedures performed during patient encounters. |
| Organizations | Healthcare facilities responsible for delivering services. |
| Providers | Clinical providers associated with patient encounters. |
| Payers | Insurance providers responsible for healthcare coverage. |

## Data Model

A dimensional star schema was implemented within SQL Server to support scalable reporting and analytical performance.

The warehouse consists of:

### Dimension Tables

- Patient
- Date
- Provider
- Organization
- Medication
- Procedure
- Condition
- Payer

### Fact Tables

- Encounter Fact
- Medication Fact
- Procedure Fact
- Condition Fact

- ## Data Governance

Although the dataset is synthetic, the solution was designed using enterprise data management principles.

Key considerations included:

- Dimensional modelling
- Consistent naming conventions
- Referential integrity
- Reusable analytics views
- Business-friendly field naming
- Scalable warehouse design

## Data Limitations

This project uses synthetic healthcare data generated by Synthea for demonstration purposes.

As a result:

- Patient records are simulated rather than real-world.
- Some provider and organizational attributes are limited.
- The dataset reflects simulated clinical workflows rather than operational hospital systems.

Despite these limitations, the project accurately demonstrates enterprise Business Intelligence concepts, healthcare analytics workflows and dashboard development techniques.
